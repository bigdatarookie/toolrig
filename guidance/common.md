# Toolrig: общий контекст

## v0.2

v0.2 разрешает реализацию availability/OpenBao/documents. Отдельного capacity seat нет. Remaining<=5% — каждый агент вправе запросить альтернативу в разрешённом пуле; без альтернативы до0, затем target с ближайшим подтверждённым reset/штатный wake. Shared home влияет на соседей OpenTour: только согласованный безопасный transition, не подмена account всем. Не менять модель/effort. Backend OpenBao, документы — конкретный стек PLATFORM#documents. Новая политика заменяет старое blanket запрещение account change только для разрешённых операций availability.


Запуск Toolrig разрешён. Все Codex seats используют `CODEX_HOME=/Users/garry/.codex-opentour` и `builtin:yolo`; общий home/permission posture не создаёт бизнес/host authority. Миссия и scope SPEC.md, текущие роли TEAM.md, механика PLATFORM.md, приёмка EVALUATION.md. Проверять live identity и своё поручение; не наследовать UI demo-культуру родителя как миссию Toolrig. Секреты и существующие user environments сохраняются.

Обычный tool call исполняется сервисом. Новые потребности/сбои становятся ограниченной native работой с владельцем и потребителем; no extra tracker/controller. Автор тестирует; назначенный компетентный неавтор review/merge без второго QA/Lead approval в разрешённом Git scope. Учиться на существенных результатах; типовые успехи не писать в Markdown. Не менять модель/permissions; account transitions допускаются только по разрешённой availability policy v0.2.

Подтверждённая готовность инструмента публикуется Support оператору и fleet-wide один раз на версию/состояние. Такое сообщение — доступная инструкция и сведения о границах, не новый допуск, обязательный ACK или основание повысить `NOT RUN`/`UNKNOWN`. Финальный владелец инструмента возвращает Support точное READY-событие; промежуточные source/PR/CI результаты не публикуются как готовность.
