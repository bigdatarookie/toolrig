# Toolrig

## Миссия

Разрабатывать и обслуживать общие инструменты хоста, браузера, документов, секретов и удалённых машин. Измеримый результат — другие риги выполняют свою проектную работу проще, быстрее и с меньшими повторными техническими вмешательствами пользователя. Tool Hub обслуживает обычные операции программно; агенты работают над новыми потребностями, исключениями и улучшениями.

## Scope

1. Локальный MCP hub: единая точка подключения, каталог, идентификация клиентов, маршрутизация, диагностика.
2. Browser service: локальный Chrome, проектные профили/сессии, сохранение авторизации, явный доступ к существующему браузеру, принадлежащие задаче вкладки и recovery.
3. Document service: определение формата, текст/таблицы, PDF-рендер и OCR по необходимости. Первая очередь PDF, изображения, DOCX, XLSX/CSV, HTML; неизвестный формат явно диагностируется.
4. Secrets service: готовый backend хранения, ссылки, разрешённое использование, ротация и восстановление; не собственная криптографическая система.
5. Remote service: зарегистрированные SSH-подключения, выполнение задач, файлы и туннели с secret references.
6. Общий lifecycle служб: Docker/Compose и launchd, установка/обновление/автозапуск/readiness/restore/rollback/удаление.

Использовать готовые компоненты и небольшие adapters. Не писать новый browser engine, execution tracker, scheduler, CRM или систему approvals. MCP/CLI — интерфейсы одних операций, не два независимых механизма исполнения.

## Ближайший этап

Пользователь разрешил запуск Toolrig после фиксации общего с OpenTour Codex home и YOLO policy. Первый этап после запуска — read-only инвентаризация существующих secrets-manager/MCP/browser tools, Docker/launchd/SSH, reuse и реальных пробелов. Реализация общего lifecycle служб начинается отдельными finite assignments; OpenTour — первый потребитель. Аудит временных Docker-окружений Polar, минимальный Hub/browser/doc consumer и разрешённое подключение к H100 выполняются только в конкретном scope. Уже работающие сервисы сохраняются до проверенной замены.

Разрешение включает запуск семи seats Toolrig с `CODEX_HOME=/Users/garry/.codex-opentour` и `builtin:yolo`. Оно не разрешает автоматически мигрировать службы, удалять ресурсы, менять credentials/модели/аккаунты других ригов или настраивать удалённые хосты. Новые покупки и непредоставленные полномочия не следуют из запуска.

## Источники фактов и границы

Текущие процессы, владельцы, ресурсы и доступы выводятся из live state, не из сохранённого snapshot. Проектные DevOps владеют поведением приложений, Toolrig — общими механизмами. Реальные endpoints/profiles/secret references — machine-local configuration, не shipped specification. См. PLATFORM/TEAM/EVALUATION.
