# Toolrig

## v0.2 — Availability, OpenBao и документные инструменты

Пользователь разрешил обновление и реализацию трёх отдельных направлений: availability service внутри Tool Hub без нового агента; кроссплатформенный OpenBao; конкретный документный стек. Семь seats, модели/effort и топология сохраняются. Native schema rig.yaml0.2 не меняется. Текущий home сохраняется до конкретного безопасного переключения по PLATFORM#availability; его общий scope с OpenTour обязательно учитывается.

Availability использует подтверждённый остаток квоты: при <=5% агент вправе запросить выбор альтернативного разрешённого аккаунта; если доступной альтернативы нет, продолжает до0. При0 выбрать аккаунт с ближайшим подтверждённым восстановлением необходимой квоты, сохранить целевое подключение/continuation и ждать штатного пробуждения. Проверка после reset и фактическое продолжение обязательны. Автоматический выбор действует только для предоставленного пользователем пула и допустимых проектов; новые покупки/непредоставленные аккаунты/смена модели не разрешаются этим правилом.

Backend секретов выбран: OpenBao, один экземпляр в контейнере с постоянным storage, bootstrap/unseal и проверенным backup/restore. macOS Keychain не обязательная зависимость. Document service: Poppler(pdftotext/pdftoppm), pdfplumber, Tesseract/OCRmyPDF по необходимости, python-docx, openpyxl, стандартный csv. Версии фиксировать и проверять совместимость macOS/Linux; исходники пользователя не изменять.

Реализация и scoped независимая проверка разрешены; это не blanket разрешение переключить весь общий home, повредить работающие сервисы, импортировать все credentials или удалить неизвестные ресурсы. Конкретные действия выполняются с сохранением потребителей и независимым review, без нового согласования каждой штатной операции.


## Миссия

Разрабатывать и обслуживать общие инструменты хоста, браузера, документов, секретов и удалённых машин. Измеримый результат — другие риги выполняют свою проектную работу проще, быстрее и с меньшими повторными техническими вмешательствами пользователя. Tool Hub обслуживает обычные операции программно; агенты работают над новыми потребностями, исключениями и улучшениями.

## Scope

1. Локальный MCP hub: единая точка подключения, каталог, идентификация клиентов, маршрутизация, диагностика.
2. Browser service: локальный Chrome, проектные профили/сессии, сохранение авторизации, явный доступ к существующему браузеру, принадлежащие задаче вкладки и recovery.
3. Document service: определение формата, текст/таблицы, PDF-рендер и OCR по необходимости. Первая очередь PDF, изображения, DOCX, XLSX/CSV, HTML; неизвестный формат явно диагностируется.
4. Secrets service: выбранный OpenBao backend хранения, ссылки, разрешённое использование, ротация и восстановление; не собственная криптографическая система.
5. Remote service: зарегистрированные SSH-подключения, выполнение задач, файлы и туннели с secret references.
6. Общий lifecycle служб: Docker/Compose и launchd, установка/обновление/автозапуск/readiness/restore/rollback/удаление.
7. Availability service: доступность Codex и безопасное продолжение по политике остатка5%/0, без отдельного агента.
8. Публикация готовности: Support постоянно принимает подтверждённые события READY инструментов Toolrig и сообщает о них оператору и всем действующим агентам OpenRig. Это событийная обязанность, а не периодический опрос или новый контроллер.

Использовать готовые компоненты и небольшие adapters. Не писать новый browser engine, execution tracker, scheduler, CRM или систему approvals. MCP/CLI — интерфейсы одних операций, не два независимых механизма исполнения.

## Ближайший этап

Пользователь разрешил запуск Toolrig после фиксации общего с OpenTour Codex home и YOLO policy. Первый этап после запуска — read-only инвентаризация существующих secrets-manager/MCP/browser tools, Docker/launchd/SSH, reuse и реальных пробелов. Реализация общего lifecycle служб начинается отдельными finite assignments; OpenTour — первый потребитель. Аудит временных Docker-окружений Polar, минимальный Hub/browser/doc consumer и разрешённое подключение к H100 выполняются только в конкретном scope. Уже работающие сервисы сохраняются до проверенной замены.

Разрешение включает запуск семи seats Toolrig с `CODEX_HOME=/Users/garry/.codex-opentour` и `builtin:yolo`. Исходное разрешение запуска не давало прав на широкие миграции/удаления/смену моделей/изменения удалённых хостов. Текущая реализация v0.2 дополнительно разрешает scoped OpenBao bootstrap и account transitions по PLATFORM#availability, сохраняя работающих потребителей и реальные границы аккаунтов. Новые покупки и непредоставленные полномочия не следуют из запуска.

## Источники фактов и границы

Текущие процессы, владельцы, ресурсы и доступы выводятся из live state, не из сохранённого snapshot. Проектные DevOps владеют поведением приложений, Toolrig — общими механизмами. Реальные endpoints/profiles/secret references — machine-local configuration, не shipped specification. См. PLATFORM/TEAM/EVALUATION.
