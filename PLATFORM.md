# Tool Hub: платформа и рабочий процесс

## availability

**Сервис доступности, не восьмой агент.** Tools Hub Engineer реализует API/механику; Infrastructure Engineer — процессы/continuity/wake; Secrets Engineer — безопасные ссылки авторизации. Lead задаёт приоритеты и разбирает исключения, Support помогает сложным случаям. Обычный выбор/ожидание/возобновление выполняются программно, без консультации Lead на каждую операцию.

### Учёт и источники

Учёт связывает аккаунт/workspace, home, реальные seats, модель/доступные окна, источник/время наблюдения, auth state, reset_at и допустимые проекты. Home не единица квоты: разные homes одного аккаунта не создают дополнительную квоту. Процент quota usage не путать с token context/cumulative token usage. Для нескольких применимых окон доступность требует всех необходимых ресурсов; остаток5% означает remaining, а не used. Unknown не0/100.

Использовать доступные в установленном Codex поддерживаемые account/read, account/rateLimits/read и rateLimits/updated; подтвердить версию/семантику/поля реальным read-only ответом. Не скрейпить credentials или выдумывать reset по строке «пять часов». Provider timestamps хранить в UTC с исходным наблюдением; в операторском выводе также Asia/Bangkok. No forced quota exhaustion для теста.

### Правила5% и0

При подтверждённом остатке<=5% каждый агент вправе вызвать инструмент выбора/переключения. Альтернатива должна быть авторизована, допускать проект/данные/модель и иметь пригодную необходимую квоту. Если альтернативы нет, продолжать текущую работу до0; не парковать заранее и не резервировать ресурс бессрочно из одного предупреждения. Не ждать обязательного low-quota вызова: сервис также обрабатывает подтверждённый provider-limit event, если заблокированный агент уже не может вызвать инструмент.

При0 выбрать разрешённый аккаунт с ближайшим подтверждённым временем восстановления всех необходимых окон; сохранить target и связанный native continuation, затем ждать штатного пробуждения. Ближайший reset одного неприменимого окна не означает доступность. Не заменять unknown reset выдуманным пятичасовым ожиданием; обеспечить ограниченное повторное наблюдение через действующий recovery path. Если есть пригодный доступный target, выполнять безопасное переключение и продолжать. При отсутствии зарегистрированного пула/времён оформить точный gap с владельцем, не приписывать несуществующую альтернативу.

Выбор/резервирование target выполняется сразу; фактическое retarget/auth/restart — в безопасной точке с сохранением задачи/разговора/неизвестных эффектов. До наступления reset не выдавать запущенный процесс за доступное исполнение и не создавать restart loop. После reset проверить фактическую доступность и начать следующий содержательный шаг. Исчерпание локального аккаунта не останавливает независимую работу остальных потребителей.

### Account pool и общий home

Разрешённый пул — metadata и ссылки на существующую авторизацию, включая scope проектов/моделей. Пользовательское поручение даёт агентам право пользоваться инструментом без повторного approval для каждого выбора в этом пуле. Не регистрировать чужой/непредоставленный аккаунт, не покупать подписки/reset credits и не менять модели/effort автоматически. Действуют условия аккаунтов/подписок и доступ проектов к данным.

Сейчас Toolrig и OpenTour разделяют home; перед изменением выявить всех затронутых живых потребителей. Нельзя менять auth общего home как локальную настройку одного seat. Конкурентные запросы используют единый operation ID и согласованный transition, не независимо перезаписывают home. Не перезапускать активно работающие соседние seats ради одного запроса. Общий home допускает только проверенный cohort переход в безопасных точках либо поддерживаемое изолированное retarget; невозможность изоляции — конкретный технический gap, который надо устранить, а не молча сменить аккаунт всем.

### Сохранение продолжения и recovery

Использовать поддерживаемые OpenRig auth/restart/resume/handover verbs после проверки текущего help/plan и runtime identity. rig auth switch восстанавливает credential state, но сам не доказывает live login; restart --keep-conversation требует подтверждения сохранённого разговора/аккаунта и actual tool turn. До исходного изменения сохранить owner/qitem/next action, native conversation ID, cwd/config/permissions и affected cohort; после подтвердить фактическую identity и полезное продолжение. Смена home не тождественна смене account: новый home может не иметь conversation/config/MCP. Не копировать/редактировать provider-owned auth/session/SQLite/transcript файлы вручную, не маскировать artifact rebuild под native resume. Если native continuity недоступна, честный supported rebuild/fork требует сохранённого restore scope и соответствующей оценки потери контекста.

Pending resume переживает restart Hub. Хранить только минимальное operation состояние, не второй task tracker; исполнение/ownership остаются native OpenRig. Использовать штатный durable wake на реальное продолжение, без параллельного cron/polling agent/controller. Снять stale blocker только по восстановлению доступности/работы, не по наступлению времени или изменению очереди. Не повторять команды с unknown business effect.

## openbao

Выбран OpenBao, один контейнер с постоянным storage и закреплённой версией, воспроизводимое описание запуска для macOS/Linux. Keychain не обязательная зависимость; pass не параллельный canonical backend. Проверить существующий secrets-manager для reuse/adapters, но не называть его рабочим store без фактов. HA/второй cluster пока не требуются.

Отдельные project/service policies, отсутствие root token у моделей/потребителей, private bootstrap credentials, безопасная передача runtime через поддерживаемый OpenBao Agent/template/process injection. Logical grants не обеспечивают OS isolation агентов одного пользователя. Не выводить секреты в контекст/argv/logs; broker endpoints не раскрываются неавторизованным клиентам. Secret references остаются стабильными при rotation. SSH использует OpenSSH/ssh-agent и проверенные host keys; credential injection не добавляет remote authority.

До подключения обязательных потребителей решить init/unseal и хранение bootstrap/recovery материалов вне защищаемого хранилища, с владельцем/доступом; не класть root/unseal значения в repo/обычные логи или постоянно открытый dev-mode. Проверить реальный container/host restart и recovery; выбрать поддерживаемую схему unseal, которая не требует постоянной ручной помощи, либо явно обозначить одноразовый недостающий bootstrap доступ/решение. Не прятать circular dependency секрета запуска OpenBao внутри закрытого OpenBao.

Проверить backup/restore в изолированной среде, scoped выдачу/отзыв, rotation и реальное применение одним разрешённым потребителем. Не переносить/ротировать все production credentials одновременно: сначала тестовый секрет, затем конкретный согласованный consumer с rollback. Сохранить текущий работающий доступ до проверки замены. Изолированный bootstrap/deployment нового service разрешён реализацией; непредоставленные host privileges/покупки/массовые миграции требуют точного отдельного решения и не останавливают независимые направления.

## documents

| Операция | Реализация |
|---|---|
| PDF текст | Poppler pdftotext |
| PDF страницы→изображения | Poppler pdftoppm |
| PDF таблицы/позиционные данные | pdfplumber |
| OCR сканов/изображений | Tesseract; OCRmyPDF для подготовки searchable PDF по необходимости |
| DOCX текст/таблицы | python-docx |
| XLSX листы/ячейки | openpyxl |
| CSV | стандартный Python csv |

Интерфейс inspect/read/render/extract_tables объединяет код, доступный через MCP и CLI. Pin compatible versions/dependencies, проверить licences/runtime macOS/Linux, не обещать абсолютную точность таблиц/OCR. Шифрованный файл требует разрешённой ссылки пароля без включения значения в ответ. Значения/formulas/cached XLSX values различать; openpyxl не вычислитель формул. Для HTML использовать существующий browser/read path, не отдельный движок.

Сначала определять формат, затем читать требуемые страницы/листы/диапазоны. OCR включать при отсутствии пригодного text layer/по явной потребности. Возвращать source page/sheet/range, предупреждения, status и ссылки на render/большие результаты; не переполнять контекст полными документами. Не выполнять macros/external content и не модифицировать оригинал; производные файлы task-owned, cleanup только своих ресурсов. Не заявлять неподдерживаемый формат успешно прочитанным.

## v02-implementation

Три отдельных finite направления с владельцами и первым consumer: availability (Hub+Infrastructure), OpenBao (Secrets+Infrastructure), documents (Automation). Независимая проверка назначается свободному компетентному неавтору с финальным техническим решением; повторного QA/Lead допуска нет. Для scope этого поручения разрешены рабочие ветки, PR и независимый merge после нужных checks; прямой push в main и широкие изменения других проектов не следуют. Приоритет инфраструктуры до фактического потребления, но существующие работающие сервисы/независимые проекты продолжаются. Штатные переключения в разрешённом account pool не требуют нового human approval; конкретно отсутствующий pool/доступ нельзя выдумать.


## Архитектура

Постоянный сервис с небольшими adapters, общими структурированными ошибками и диагностикой. Использовать готовый MCP SDK/серверы; выбранный secrets backend — OpenBao по разделу openbao. Версии фиксируются в реализации. Предпочтение локальному endpoint; stdio adapter при необходимости обращается к тому же сервису. Доступ к инструментам не требует живого агента Toolrig.

Клиент аутентифицируется отдельно от переданного им текста rig/seat. Права связывают потребителя, ресурс и операцию. Секреты целевого сервиса не служат универсальной аутентификацией Hub. Локальный endpoint не считать автоматически защищённым. Общие per-project grants не являются OS sandbox для YOLO-агентов того же пользователя: строгая изоляция потребует отдельных системных границ.

## Browser и документы

Использовать готовую автоматизацию Chrome, отдельные проектные профили и явно выбранный доступ к существующему браузеру. Каждая сессия/вкладка имеет владельца; одна общая вкладка не управляется конкурентно несколькими задачами. Сохранять авторизацию без раскрытия cookies модели. MFA/обязательное действие человека — конкретный resumable этап. Не закрывать пользовательские браузеры, чужие вкладки или профили.

Документный adapter определяет формат, допускает страницы/листы/диапазоны, возвращает текст/таблицы/ссылки на render и предупреждения. OCR не выдаёт распознанное за исходное значение; чтение значений и формул различимо. Не загружать целый документ в контекст при доступном извлечении нужного фрагмента. Не обещать поддержку любого файла.

## Secrets и remote

Backend — OpenBao; существующий secrets-manager сначала проверить как возможный adapter, не считать готовым backend без evidence. Canonical secret имеет ссылку, владельца, разрешённых потребителей и порядок ротации/recovery. Credentials передаются нужному runtime; значение модели выдаётся лишь если операция действительно требует этого и разрешена. Не копировать ключи в репозитории/контекст/argv/логи. Ротация проверяет реальное подключение и сохраняет работающий путь до подтверждения замены.

SSH target хранит адрес/пользователя/проверенный host key и secret reference; поддерживать sessions/run/files/tunnels в предоставленных полномочиях. Не отключать проверку host key ради удобства. Не изобретать credentials и не расширять remote privileges из наличия подключения.

## Docker, launchd и службы

Infrastructure Engineer ведёт фактическую инвентаризацию через системные инструменты и согласованное описание установки. Для службы известны понятное имя, назначение, проектный владелец, версия, ресурсы, durable state, безопасные credential references, readiness и stop/update/uninstall. Не создавать отдельную базу задач/контроллер; machine state — runtime/config, product instructions — docs.

Общий service lifecycle разрабатывается и обслуживается Toolrig; project DevOps поставляет прикладной контракт. Новая версия заменяет старую установку с проверкой здоровья, consumer effect и отсутствия прежних экземпляров. Сохранить rollback; uninstall службы не удаляет автоматически её DB/volumes. launchd entry и UI-наименование должны быть понятны пользователю, а не называться случайным wrapper executable без объяснения.

Docker-аудит различает containers, Compose projects, images, networks, volumes, OpenRig rigs и browser sessions. Сначала установить владельца/назначение. Удалять только подтверждённо одноразовые ресурсы в разрешённом scope после сохранения полезного; blanket prune с volumes не способ уборки. Исправлять причину накопления: task ownership, lifecycle hook и устойчивый cleanup. Не трогать неизвестные/рабочие ресурсы.

## PR и применение

Автор отвечает за unit-тесты и авторскую отладку. CI — повторяемые проверки; reviewer — оценка изменения и исключений, не ручное повторение всех автоматических проверок. Lead назначает одного компетентного свободного неавтора, фиксируя контекст и область независимости в существующем задании. Назначенный reviewer владеет финальным решением/merge, без второго допуска QA/Lead. Если он исправил существенную часть, другой неавтор проверяет её. Новые компоненты проверяются через реального потребителя; одинаковые неизменённые пути повторно не проходят без основания.

Для авторизованной реализации v0.2 действуют рабочие ветки/PR/независимый merge по v02-implementation; отдельного Lead approval на каждый PR нет.

## Непрерывность и опыт

Lead удерживает постоянный outcome, исполнители сохраняют следующий шаг/содержательную передачу. Использовать native queue/handoff и существующие wake mechanisms, не второй scheduler. Локальное препятствие не закрывает независимые фронты. Оператор решает вопросы вне полномочий, не диспетчер каждого вызова.

Программные операционные логи содержат outcome/duration/error code/объём, с redaction и retention; не секреты/сырые private bodies. Существенный инцидент, действие и наблюдённый эффект — существующий mission NOTES; повторяемый урок — LEARNED. Успешные типовые вызовы/здоровые hourly проверки не пишутся в Markdown. Эпизод доступа сохраняет новое/необычное, blocking effect, missing tool и working method без повторения подробного описания известного успеха.

## Проверка перед развёртыванием

Пользователь разрешил запуск Toolrig. Оператор перед запуском проверяет topology/context/handoff, agent refs и фиксированные choices: `CODEX_HOME=/Users/garry/.codex-opentour`, `permission_policy: builtin:yolo`, workspace `/Users/garry/Documents/git/toolrig`, remote `bigdatarookie/toolrig`. Первый этап после запуска включал read-only inventory. Текущие исполнимые направления v0.2 — availability/OpenBao/documents по v02-implementation; не ждать нового разрешения начать их реализацию. Запуск не регистрирует дополнительные timers и не разрешает сам по себе миграцию служб/секретов, изменение хоста или удаление ресурсов.
